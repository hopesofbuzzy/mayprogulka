# Факт-лист: OCR-система «Майской прогулки» (обновлено после feature/ai-ocr-model)

*Сжатый набор фактов для презентации/защиты. Все цифры — из бенчмарка `benchmark/run_benchmark.py` (seed=42): 2 реальных фото + 36 синтетических анкет с деградациями «как фото со смартфона». Пайплайн при замерах не изменялся.*

---

## Что это

OCR-конвейер оцифровки бумажных анкет участников на стартовой регистрации: фото со смартфона → структурированная запись. Полностью локально (onnxruntime, CPU ~4–5 с/анкета), без GPU и облачных API.

**5 стадий:** верификация и выравнивание (ArUco / чёрные квадраты / контур листа → 1200×1600) → динамическая привязка строк по печатным меткам → OMR чекбоксов → гибрид из 3 ONNX-моделей (PP-OCRv6 Medium Cyrillic + дообученная HandwrittenBoxNet на 73 класса + RapidOCR Latin, символьный фьюжн) → валидация и словари → шлюз APPROVED / REQUIRES_REVIEW.

## Ключевые метрики (A/B: main → feature/ai-ocr-model)

| Показатель | Main | Ветка |
|---|---|---|
| Реальное фото, шаблон «чёрные квадраты» (11 полей) | 5/11 (45%) | **9/11 (82%)** |
| Реальное фото, шаблон ArUco v2 (11 полей) | — | **10/11 (91%)** |
| Синтетика medium: анкеты целиком верны | 17% | **25%** |
| Синтетика hard: фамилия / город / карта | 8% / 50% / 0% | **83% / 100% / 42%** |
| Латентность (CPU) | ~5 с | **4–5 с** |

Что починил фикс сетки ячеек (реальное фото): имя `СРМ → ГЕОРГИЙ`, дата `потеряно → 14.06.2007`, телефон `9134567 → 9123456789`, ранее участв. `0 → 3`.

## Как считать метрики корректно (честные оговорки)

- Синтетика заполняется шрифтом Arial Bold, а не рукописью: она проверяет **устойчивость конвейера к качеству съёмки**, но завышает результат для живого почерка. Реальная точность — по двум фото выше.
- Ложные пропуски не исправлены: на средних искажениях **100% анкет одобряется (APPROVED) при 25% целиком верных** — шлюз проверяет только дату/телефон, а уверенность модели не калибрована.
- Известные остаточные ошибки: подстановка О/А→1 в e-mail (1 символ), потеря последней цифры № карты на одном из шаблонов.

## Что работает хорошо (проверено бенчмарком)

- Выравнивание: 4 каскадные стратегии; реальное фото (поворот 90°, изгиб, тень) выравнивается корректно, 0.2 с.
- Сегментация после сеточной достройки: телефон 10/10, дата 6/8, «ранее участв.» 2/2 ячеек.
- Словари постобработки: `ЕАТЕРНБУРГ → ЕКАТЕРИНБУРГ`, восстановление домена `mail.ru` из трёх сырых вариантов.
- OMR дистанции и пола: 100% на синтетике всех уровней.

## Роадмап (ранжировано по эффекту)

1. **Калибровка confidence + шлюз APPROVED по всем полям** — убирает ложные пропуски (главный риск данных).
2. **Точечные правки e-mail декодера** — устранить регрессию О/А→1.
3. **Дообучение поклеточной модели на 50–300 реальных фото** — снимает остаточные путаницы (6/8/0, 9/1, Г/С); разметка почти бесплатна: текст поля транскрибируется один раз, клетки нарезаются сеткой автоматически.
