# OCR-оцифровка анкет «Майская прогулка» — материал для слайдов

*Сжатые таблицы и метрики. Все цифры измерены бенчмарком `benchmark/run_benchmark.py` (seed=42, 2 реальных фото + 36 синтетических анкет).*

---

## Слайд 1. Проблема → решение
- До **30–40%** участников регистрируются очно в день старта: бумажные анкеты, очереди, ошибки ручного ввода
- Решение: фото бланка → готовая запись за **~5 с на обычном CPU** — без GPU, облака и платы за скан

## Слайд 2. Архитектура: 5 стадий, 3 локальные ONNX-модели
| Стадия | Что делает | Время |
|---|---|---|
| Выравнивание | ArUco / чёрные квадраты / контур листа → холст 1200×1600 | 0.2 с |
| Привязка строк | OCR печатных подписей + интерполяция | ~1 с |
| OMR | Чекбоксы дистанции/пола, компенсация освещения | <0.1 с |
| Распознавание | PP-OCRv6 + HandwrittenBoxNet (73 кл.) + RapidOCR Latin | ~2 с |
| Валидация | Словари, даты, телефоны → APPROVED / REQUIRES_REVIEW | <1 с |

## Слайд 3. Реальные фото: до → после фикса (A/B)
| Метрика | Main | Ветка |
|---|---|---|
| Шаблон «чёрные квадраты» | 5/11 (45%) | **9/11 (82%)** |
| Шаблон ArUco v2 | — | **10/11 (91%)** |
| Имя / дата / телефон | потеряны | **✅ верно** |

## Слайд 4. Устойчивость к качеству съёмки (36 анкет, seed=42)
| Уровень | Целиком верные: main → ветка |
|---|---|
| Лёгкие | 67% → 50%* |
| Средние | 17% → **25%** |
| Тяжёлые | 0% → 0% (фамилия 8→**83%**, город 50→**100%**, карта 0→**42%**) |

\* регрессия e-mail на 1 символ — в работе

## Слайд 5. Надёжность потока
- Бракованные анкеты не попадают в БД: **REQUIRES_REVIEW** выставлен верно на всех реальных фото
- Работает офлайн, лицензия моделей открытая; волонтёр подтверждает только спорные поля

## Слайд 6. Ограничения → роадмап
1. Ложные пропуски: 100% APPROVED при 25% верных (medium) → **калибровка confidence + шлюз по всем полям**
2. E-mail: подстановки О/А→1 → точечная правка декодера
3. Потолок на рукописи → **дообучение на 50–300 реальных фото** (разметка автоматизирована нарезкой клеток)
