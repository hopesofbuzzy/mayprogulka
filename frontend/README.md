# Майская прогулка — фронтенд

Реализованы TASK-01/01.1 (публичная часть), TASK-02 (аккаунт/сессия), TASK-03/03.1 (участники) и TASK-04 (тестовая оплата своего участника, проверка статуса и условный PDF). React + TypeScript strict + Vite, React Router Data Mode, CSS Modules, локальная SVG-графика. FastAPI — отдельное приложение; его код и настройки не изменяются.

## Запуск в Windows PowerShell

Нужен установленный Node.js 26.x с npm. Проверено на Node **26.13.0**, npm **11.20.0**. Команды выполняются из `frontend`:

```powershell
cd D:\projects\mayprogulka\frontend
node --version
npm.cmd --version
npm.cmd ci
npm.cmd run dev
```

Открыть адрес, который напечатает Vite (обычно `http://127.0.0.1:5173`). Если PowerShell разрешает обычный `npm`, можно использовать его. Если `npm.cmd` отсутствует в PATH, проверьте установку Node. В проверенном окружении доступен `C:\Program Files\nodejs\npm.cmd`; перед запуском можно добавить эту директорию в PATH **текущего** PowerShell. Менять execution policy не нужно.

## API и запуск без FastAPI

Приложение вызывает `GET /api/v1/routes`, `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/participants/my`, `POST /api/v1/participants/register` и `POST /api/v1/participants/{participant_id}/pay` через один типизированный клиент. `baseUrl` пустой: префикс уже содержится в контракте. Vite проксирует `/api` на `http://127.0.0.1:8000`. Чтобы изменить адрес локального сервера:

```powershell
Copy-Item .env.example .env.local
# Измените API_PROXY_TARGET в .env.local, затем перезапустите Vite.
```

`API_PROXY_TARGET` доступен конфигурации Vite, не экспортируется в браузер. Секреты в env не нужны. Файлы `.env*` игнорируются, `.env.example` остаётся доступен для Git.

Без FastAPI главная, формы и 404 открываются; каталог и отправка форм показывают ошибки сервиса, без фиктивного успеха. При проверке отсутствующий сервер давал **502** через dev proxy и отказ соединения при прямом GET. Приложение не включает моки автоматически. В тестах ответы подменяются явно, реальные записи не создаются.

Каталог показывает данные всех лет из ответа, с явным годом и статусом каждого маршрута. Неактивные записи помечены как недоступные для регистрации. Активность не объявляется открытой регистрацией. Нет выдуманных расстояний, дат, мест старта и цен.

`description` и `map_url` допускают null/отсутствие. До согласования источников карт открываются только HTTP(S)-адреса текущего origin, включая относительные пути; при внешнем/небезопасном адресе отображается сообщение о предоставленной карте без активной ссылки. Адреса сторонних серверов не превращаются в ссылки автоматически. Ни SVG главной, ни графика из референсов не выдаются за географическую карту.

Загрузка ограничена 15 секундами, отмена передаётся через AbortSignal. Автоматические повторы и обновление при фокусе/восстановлении сети отключены. Ошибка содержит понятное сообщение и кнопку повторного GET. HTTP 401/403/404/409/422 и другие статусы обрабатываются без вывода сырого тела ошибки.

## Сессия TASK-02

Регистрация отправляет только `username/email/password`, вход — `username/password`. Повтор пароля существует только в UI. Регистрация 201 сразу авторизует; вход подтверждается 200 и корректным TokenResponse. Ограничение пароля при регистрации — 6–72 символа. Нет автоматических повторов POST, повторная отправка блокируется до ответа. Поля сохраняются при ошибках. 422 привязывается к полям по `detail[].loc`; сырые серверные сообщения, HTML и секреты не выводятся. При потере ответа регистрации аккаунт мог быть создан: сначала попробуйте войти, не повторяйте регистрацию вслепую.

Сессия хранится **только в памяти вкладки** в `shared/session/store.ts`. Обновление страницы сбрасывает вход. LocalStorage, sessionStorage, cookies, IndexedDB и сохранение токенов на диск не используются. Локальный выход очищает сессию и приватный кеш и открывает вход; **он не отзывает серверный Bearer-токен**. Refresh/logout API отсутствуют. Восстановление после refresh не реализовано.

Клиент добавляет Bearer только к путям, для которых текущий OpenAPI декларирует security; публичные auth и routes не получают токен. 401 от актуального защищённого запроса завершает текущую сессию; 403, 5xx и сетевой сбой её не уничтожают. Запросы помечаются поколением сессии: старый 401 не завершит новый вход, старый успешный auth-ответ после выхода/ухода с формы не восстановит сессию.

Для приватных TanStack Query-данных используется `meta: { private: true }` либо ключ с первым элементом `'private'`. При выходе/смене аккаунта такие запросы отменяются и удаляются **до уведомления UI**, кеш мутаций очищается; публичный routes-кеш сохраняется. Список участников TASK-03 использует обе маркировки и поколение сессии. `GET /auth/me` не вызывается интерфейсом и не используется как профиль: его схема тела не описана. Тесты клиента используют его только для проверки транспорта/статусов.

`RequireAuth` охраняет `/account` и страницы участников по текущей клиентской сессии. Возврат после входа допускается только на поддерживаемые внутренние пути, включая `/account/participants/new`, числовой `/account/participants/:id` и `/account/participants/:id/pay`; внешние адреса, опасные закодированные символы и неподдерживаемые пути отклоняются. Роль из TokenResponse не предоставляет серверных полномочий.

Отчёт TASK-02 и снимки находятся в игнорируемых `../local_docs/TASK-02-REPORT.md` и `../local_docs/task-02-artifacts/`. Для подтверждения real-API необходимы согласованная тестовая база и тестовые учётные данные; изолированные тестовые ответы такого подтверждения не дают.

## Участники TASK-03

`/account` загружает `GET /participants/my` без фильтра route_id. Есть loading, пустой список, ошибка, ручное обновление и ссылки на детали. Каждый участник имеет отдельные ID и номер анкеты; номер физической карты показывается только из ответа и остаётся строкой с ведущими нулями. Старт, финиш и оплата не вычисляются локально. Неизвестные платёжные статусы отображаются нейтрально, а не как «Оплачено».

`/account/participants/new` — массив независимых анкет со стабильными UI-ключами. У каждого фамилия/имя, необязательное отчество, календарная дата рождения без возрастных ограничений, male/female, свой активный маршрут, email и телефон. Маршруты берутся из существующего query: название/год/дистанция видны, route_id сериализуется числом. Неактивный/исчезнувший маршрут отправить нельзя. Телефон — непустая строка без жёсткой маски; одинаковые семейные контакты не блокируются. Поддержка этих контактов и разных маршрутов на реальном сервере остаётся отдельной проверкой Q-10/15/16.

Один явный submit отправляет `{ participants: [...] }`. Pending блокирует изменение/удаление строк и повтор POST. Ошибки 422 переводятся с `detail[].loc` на ключи именно отправленных строк; неизвестные пути остаются общей безопасной ошибкой. После 201 с валидным ответом показаны отдельные form_id и номер операции registration_id. Приватный список инвалидируется и заново читается из GET. Если GET не удался, подтверждённый 201 сохраняется, повторяется только загрузка списка — локальные данные не подменяют серверный список.

При обрыве/таймауте/5xx/некорректном ответе POST исход считается неопределённым. Форма остаётся заполненной, автоматического повтора нет. «Проверить в личном кабинете» загружает актуальный GET прямо рядом с формой, сохраняя ввод. Даже пустой список не доказывает отсутствия регистрации. Повторный POST требует явного подтверждения риска дублей; idempotency key в контракте нет. Изменение формы сбрасывает это подтверждение. На смене сессии форма, ошибки и результат очищаются по её поколению; PII не сохраняется в storage или Query key.

`/account/participants/:id` читает только собственный список и ищет числовой ID; отдельного GET участника нет. Некорректный/отсутствующий ID не открывает чужую запись. Полные личные данные, история КП, редактирование и удаление не реализованы. Из карточки есть переход к тестовой оплате TASK-04. Готовность регистрации не выводится из is_active или максимального года.

Отчёт и снимки: `../local_docs/TASK-03-REPORT.md`, `../local_docs/task-03-artifacts/`. В обычном приложении нет моков. Успешные сценарии unit/browser проверяются на изолированном транспорте; реальные записи разрешено создавать только на отдельно согласованной тестовой базе.

Исторические разовые browser-проверки TASK-01..04 сохранены в локальных артефактах. В TASK-05 добавлен переносимый Playwright Test; текущий запуск описан ниже, без зависимости от внешнего runtime или пользовательского абсолютного пути.

## Переносимые проверки TASK-05

Это **mock browser E2E**, полностью изолированный от живого FastAPI. После чистого клона, из `frontend/`:

```powershell
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

Playwright Test **1.64.1** закреплён как dev-only зависимость и в lock-файле, Chromium устанавливается отдельно. Применяются только синтетические данные и созданные в памяти mock-credentials; настоящие аккаунты/БД не нужны. На POSIX используйте `npm`/`npx`. `npm run test:e2e:headed -- --project=mobile` открывает видимый Chromium при ручной отладке.

Тесты запускают собственный Vite на **127.0.0.1:4179** с `--strictPort`, не переиспользуют чужой процесс. Если порт занят — освободите его или согласованно измените URL и порт в `playwright.config.ts`; автоматического перехода на случайный сервер нет. Только в `mode=e2e` dev proxy отключён. Test-context перехватывает API: любой неожиданный метод/путь или внешний origin блокируется и проваливает обычный сценарий, без fallback к backend. В runtime-приложение mocks не добавлены.

11 сценариев выполняются в четырёх viewport: 1280×720, 390×844, 360×800, 768×1024 — **44 запуска**. Проверяются публичная сеть/ошибки/404, signup/login/logout, семейная регистрация, индексные 422 и 408, осознанный повтор регистрации, тестовая оплата с GET, неизвестный исход, пустая PDF policy, смена аккаунта при поздних 200/401, back/forward/reload, переполнение и pageerror. Отдельный сценарий проверяет сам запрет неожиданного GET/POST и внешней сети. E2E не импортирует вторую сессию и не меняет production allowlist.

Результаты и минимальные скриншоты автоматически сохраняются в `../local_docs/task-05-artifacts/`; trace/video/HAR отключены для исключения credentials из артефактов. Скриншоты содержат только синтетические записи. `npm test` остаётся Vitest-набором из `src/`, E2E и Node probe-тесты не смешиваются с его счётчиком. E2E TypeScript проверяется отдельным `tsconfig.e2e.json` в общей команде typecheck.

Для **отдельного read-only** probe нужен явно заданный согласованный тестовый origin:

```powershell

npm.cmd run integration:preflight
Remove-Item Env:LIVE_API_ORIGIN
npm.cmd run test:preflight

Probe делает только GET `/openapi.json` и GET `/api/v1/routes` без Bearer/cookies, повторов или следования редиректам; проверяет HTTP/JSON, семь P0 и расхождения с tracked contract, ничего не перезаписывает. HTML вместо JSON не считается успехом. Не входит в test/build/E2E. Тесты probe используют контролируемый fetch без сети/БД.

Воспроизводимый live-runbook, таблица окружения, матрица кодов/полей, вопросы API и **отдельный запрещённый по умолчанию раздел реальных изменяющих smoke**: [INTEGRATION_TESTING.md](./INTEGRATION_TESTING.md). Без явного разрешения владельца тестовой БД не создавайте аккаунты, участников, оплаты или карты. GET schema/routes не подтверждает все POST; `GET /auth/me` не даёт DTO профиля. ## Тестовая оплата TASK-04

`/account/participants/:id/pay` защищён тем же guard. Идентичность и `payment_status` берутся из собственного списка; POST допускается только при свежем успешном GET с `pending`. `paid` блокирует повтор; любое другое значение отображается нейтрально и требует уточнения. Явный баннер «Тестовая оплата — без списания денег» находится рядом с выбранным участником. Способы `card` / `sbp` отправляются явно, без суммы, валюты и банковских данных.

Один submit отправляет точный `{ payment_method }` к целочисленному `participant.id`. Быстрые клики, Enter, remount и восстановление сети не повторяют POST. Успех транспорта требует HTTP 200 и строк `status` / `payment_id`; затем отменяется устаревший GET и обновляется существующий приватный список. Только `payment_status === 'paid'` из GET обозначается как «Оплачено». `PaymentResponse.status` и технический номер операции показаны отдельно и не выдаются за банковское подтверждение. Если GET не отвечает, возвращает pending/неизвестный статус или не содержит участника, остаётся предупреждение и отдельный повтор GET.

HTTP 408, timeout/AbortError, обрыв, 5xx и некорректный ответ считаются неизвестным исходом. 403/404/409/422 — безопасный явный отказ; актуальный 401 обрабатывает существующая сессия. После любой отправки **повторный POST для этой записи в текущей сессии не предоставляется**: доступны обновление GET и возврат. Это консервативное решение при отсутствии гарантии идемпотентности; пустой/pending GET не снимает риск. Отдельного ручного POST-retry с checkbox в TASK-04 нет.

Состояние операции хранится только в приватном Query-кеше `['private', 'payment', epoch, participant.id]`, `meta.private=true`, без автоматического query POST. Маркер переживает навигацию в текущей сессии. Уход во время pending отменяет клиентский запрос и оставляет предупреждение, что серверная операция могла пройти. Logout/switch очищает маркер, результат, идентичность и PDF. Browser refresh теряет memory-only сессию и URL; возврат после входа сначала выполняет GET, без автоматической оплаты.

**PDF fail-closed:** `safeFormPdfUrl` разрешает лишь HTTP(S) того же origin, точный явно разрешённый root-relative путь к `.pdf`, без query, fragment, credentials, `%`-кодирования, пробелов, обратных слешей, protocol-relative URL и переходов `..`. Список точных путей `features/payments/pdfPolicy.ts` сейчас **пуст**: контракт не определяет host/path и обычный доступ без Bearer. Пока бэкенд не подтвердит конкретные пути, любой непустой URL даёт «Адрес анкеты требует уточнения» без активной ссылки. Это блокер реального PDF, а не придуманный `/forms` endpoint. `null`/отсутствие/пустая строка дают «Анкета пока недоступна».

После согласования точного пути безопасная ссылка из подтверждённого ответа POST может открываться на той же странице с `target=_blank`, `rel=noopener noreferrer`, `referrerPolicy=no-referrer` и инструкцией распечатать анкету. Она не восстанавливается повторной оплатой. Signed/query URLs, внешний backend-origin, авторизация Bearer при скачивании и скрытые серверные редиректы требуют отдельного согласования; обходного blob-fetch или токена в URL нет. Проверка URL не доказывает MIME/содержимое файла либо поведение сервера при переходе.

Новые тесты проверяют транспорт, неизвестный результат, изоляцию сессий/участников и PDF-политику. Разрешённый PDF-путь в тестах задан **только тестовой фикстурой**; в обычном приложении allowlist не расширена. Chromium-проверки и снимки: `../local_docs/task-04-artifacts/`, подробный отчёт: `../local_docs/TASK-04-REPORT.md`. FastAPI на 127.0.0.1:8000 недоступен; реальные изменение БД, доступ к PDF и работа сервера не подтверждены.

Вопросы к бэкенду: реальные строки обоих статусов и задержка GET; идемпотентность pay; точные PDF origin/path, обычный доступ без Bearer и редиректов, signed/одноразовые ссылки и срок жизни; получение анкеты после потери ссылки. Доставка email, настоящие платежи и служебные роли не реализованы.

## Структура

- `src/app` — bootstrap, QueryClientProvider и маршруты Data Mode; каталог загружается отдельным модулем.
- `src/layouts` — общая шапка, навигация и управление фокусом.
- `src/pages` — публичные страницы, аккаунт, список/форма/детали участников и 404.
- `src/features/auth` — формы API, AuthProvider, guard, выход и безопасный возврат.

## Сборка и размещение

`npm.cmd run build` создаёт статические файлы в `dist`. `npm.cmd run preview` позволяет посмотреть сборку локально, но не заменяет production-сервер. Dev proxy настроен только для `dev`: в preview/production адрес API должен обслуживаться отдельно.

Для размещения нужен **SPA fallback** на `index.html` для клиентских URL, включая прямые `/routes`, `/login`, `/signup`, `/account/participants/*` и неизвестные пути для React-404. `/api/v1/*` должен направляться в FastAPI и возвращать JSON/ошибку API, не HTML приложения; ресурсы раздаются как статика. Необходимо отдельно согласовать HTTPS, reverse proxy, кеширование, реальные публичные данные и SEO. Серверная конфигурация не менялась, production не проверен. Настоящие платежи, доставка/повторное получение PDF, служебные страницы и SSR/PWA остаются вне TASK-04.
