# Майская прогулка — фронтенд

Реализованы TASK-01/01.1 (главная, каталог, 404 и адаптивность) и TASK-02: `/signup`, `/login`, клиентская сессия и защищённая оболочка `/account`. React + TypeScript strict + Vite, React Router Data Mode, CSS Modules, локальная SVG-графика. FastAPI — отдельное приложение; его код и настройки не изменяются.

## Запуск в Windows PowerShell

Нужен установленный Node.js 26.x с npm. Проверено на Node **26.13.0**, npm **11.20.0**. Команды выполняются из `frontend`:

```powershell
cd D:\projects\mayprogulka\frontend
node --version
npm.cmd --version
npm.cmd ci
npm.cmd run dev
```

Открыть адрес, который напечатает Vite (обычно `http://127.0.0.1:5173`). Если PowerShell разрешает обычный `npm`, можно использовать его. Если `npm.cmd` отсутствует в PATH, проверьте установку Node. В проверенном окружении доступен `C:\Program Files\nodejs\npm.cmd`; перед запуском можно добавить эту директорию в PATH **текущего** PowerShell. Менять execution policy не нужно.

## API и запуск без FastAPI

Приложение вызывает `GET /api/v1/routes`, `POST /api/v1/auth/register` и `POST /api/v1/auth/login` через один типизированный клиент. `baseUrl` пустой: префикс уже содержится в контракте. Vite проксирует `/api` на `http://127.0.0.1:8000`. Чтобы изменить адрес локального сервера:

```powershell
Copy-Item .env.example .env.local
# Измените API_PROXY_TARGET в .env.local, затем перезапустите Vite.
```

`API_PROXY_TARGET` доступен конфигурации Vite, не экспортируется в браузер. Секреты в env не нужны. Файлы `.env*` игнорируются, `.env.example` остаётся доступен для Git.

Без FastAPI главная, формы и 404 открываются; каталог и отправка форм показывают ошибки сервиса, без фиктивного успеха. При проверке отсутствующий сервер давал **502** через dev proxy и отказ соединения при прямом GET. Приложение не включает моки автоматически. В тестах ответы подменяются явно, реальные записи не создаются.

Каталог показывает данные всех лет из ответа, с явным годом и статусом каждого маршрута. Неактивные записи помечены как недоступные для регистрации. Активность не объявляется открытой регистрацией. Нет выдуманных расстояний, дат, мест старта и цен.

`description` и `map_url` допускают null/отсутствие. До согласования источников карт открываются только HTTP(S)-адреса текущего origin, включая относительные пути; при внешнем/небезопасном адресе отображается сообщение о предоставленной карте без активной ссылки. Адреса сторонних серверов не превращаются в ссылки автоматически. Ни SVG главной, ни графика из референсов не выдаются за географическую карту.

Загрузка ограничена 15 секундами, отмена передаётся через AbortSignal. Автоматические повторы и обновление при фокусе/восстановлении сети отключены. Ошибка содержит понятное сообщение и кнопку повторного GET. HTTP 401/403/404/409/422 и другие статусы обрабатываются без вывода сырого тела ошибки.

## Контракт и проверки

`../contracts/openapi.current.json` — побайтовая копия предоставленного JSON: OpenAPI **3.1.0**, API **0.1.0**, **20 путей / 22 операции**. Наличие всех операций в типах не означает их проверенную работу. Генерация не требует запущенного сервера:

```powershell
npm.cmd run api:generate
npm.cmd run api:check
npm.cmd run typecheck
npm.cmd run lint
npm.cmd test
npm.cmd run build
```

`api:check` повторно генерирует типы в памяти, сравнивает с `src/shared/api/schema.d.ts` с учётом Windows CRLF/LF, проверяет версии, количество операций и отсутствие двойного префикса. Generated-файл вручную не редактировать. После согласованного обновления контракта выполнить генерацию и все проверки.

Тесты Vitest + Testing Library проверяют главную, каталог, 404 и мобильное меню, а также формы, DTO, валидацию, guard, безопасный возврат, выход, приватный кеш и изоляцию старых запросов. Это проверки с контролируемыми ответами, не real-API smoke. `test:watch` запускает режим разработки тестов.

## Сессия TASK-02

Регистрация отправляет только `username/email/password`, вход — `username/password`. Повтор пароля существует только в UI. Регистрация 201 сразу авторизует; вход подтверждается 200 и корректным TokenResponse. Ограничение пароля при регистрации — 6–72 символа. Нет автоматических повторов POST, повторная отправка блокируется до ответа. Поля сохраняются при ошибках. 422 привязывается к полям по `detail[].loc`; сырые серверные сообщения, HTML и секреты не выводятся. При потере ответа регистрации аккаунт мог быть создан: сначала попробуйте войти, не повторяйте регистрацию вслепую.

Сессия хранится **только в памяти вкладки** в `shared/session/store.ts`. Обновление страницы сбрасывает вход. LocalStorage, sessionStorage, cookies, IndexedDB и сохранение токенов на диск не используются. Локальный выход очищает сессию и приватный кеш и открывает вход; **он не отзывает серверный Bearer-токен**. Refresh/logout API отсутствуют. Восстановление после refresh не реализовано.

Клиент добавляет Bearer только к путям, для которых текущий OpenAPI декларирует security; публичные auth и routes не получают токен. 401 от актуального защищённого запроса завершает текущую сессию; 403, 5xx и сетевой сбой её не уничтожают. Запросы помечаются поколением сессии: старый 401 не завершит новый вход, старый успешный auth-ответ после выхода/ухода с формы не восстановит сессию.

Для приватных TanStack Query-данных используется `meta: { private: true }` либо ключ с первым элементом `'private'`. При выходе/смене аккаунта такие запросы отменяются и удаляются **до уведомления UI**, кеш мутаций очищается; публичный routes-кеш сохраняется. Реальных приватных запросов к участникам в TASK-02 нет. `GET /auth/me` не вызывается интерфейсом и не используется как профиль: его схема тела не описана. Тесты клиента используют его только для проверки транспорта/статусов.

`RequireAuth` охраняет `/account` по текущей клиентской сессии. Возврат после входа допускается только на поддерживаемые внутренние пути; внешние адреса и неподдерживаемые маршруты отклоняются. Роль из TokenResponse не предоставляет серверных полномочий. Кабинет — оболочка без списка участников, оплаты, PDF и служебных разделов.

Отчёт TASK-02 и снимки находятся в игнорируемых `../local_docs/TASK-02-REPORT.md` и `../local_docs/task-02-artifacts/`. Для подтверждения real-API необходимы согласованная тестовая база и тестовые учётные данные; изолированные тестовые ответы такого подтверждения не дают.

В этой итерации дополнительно выполнена разовая браузерная проверка в Chromium через имеющийся Playwright; он не добавлен в зависимости проекта. Снимки и результаты находятся в игнорируемой `.artifacts/`. Полноценный переносимый набор браузерной регрессии пока не настроен. Результаты и ограничения: `../docs/frontend/TASK-01-REPORT.md`.

## Структура

- `src/app` — bootstrap, QueryClientProvider и маршруты Data Mode; каталог загружается отдельным модулем.
- `src/layouts` — общая шапка, навигация и управление фокусом.
- `src/pages` — главная, каталог, формы аккаунта, оболочка кабинета и 404.
- `src/features/auth` — формы API, AuthProvider, guard, выход и безопасный возврат.
- `src/features/routes` — один типизированный GET и настройки Query.
- `src/shared/api` — один openapi-fetch-клиент, ошибки, сгенерированные типы.
- `src/shared/session` — memory-only store и поколение сессии.
- `src/shared/styles` — токены, базовые стили и адаптивность.
- `src/shared/assets` — векторные логотип и сцена.
- `src/test`, `*.test.ts` — автоматические проверки.
- `scripts/check-api.mjs` — проверка воспроизводимости контракта.

Roboto поставляется локально через `@fontsource/roboto` (SIL OFL 1.1, см. `THIRD_PARTY_LICENSES.txt`). Это близкая выбранная гарнитура; исходный скриншот не доказывает название оригинального шрифта. Внешних хостов шрифтов и изображений нет.

## Сборка и размещение

`npm.cmd run build` создаёт статические файлы в `dist`. `npm.cmd run preview` позволяет посмотреть сборку локально, но не заменяет production-сервер. Dev proxy настроен только для `dev`: в preview/production адрес API должен обслуживаться отдельно.

Для размещения нужен **SPA fallback** на `index.html` для клиентских URL, включая прямые `/routes`, `/login`, `/signup`, `/account` и неизвестные пути для React-404. `/api/v1/*` должен направляться в FastAPI и возвращать JSON/ошибку API, не HTML приложения; ресурсы раздаются как статика. Необходимо отдельно согласовать HTTPS, reverse proxy, кеширование, реальные публичные данные и SEO. Серверная конфигурация в этой задаче не менялась, production не проверен. Регистрация участников, платежи, PDF, служебные страницы, SSR/PWA остаются вне TASK-02.
