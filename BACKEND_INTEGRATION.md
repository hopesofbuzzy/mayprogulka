## 1. Архитектура подключения и `api_config.js`

Все API-вызовы во всех HTML-файлах проходят через функцию `mpApiUrl(path)` из файла [`api_config.js`](api_config.js):

- По умолчанию `DEFAULT_API_BASE_URL = ''` (запросы идут на `/api/...` текущего домена).
- Чтобы направить фронт на внешний бэкенд (например, `http://localhost:8000`), измените `DEFAULT_API_BASE_URL` в `api_config.js` **или** откройте страницу с query-параметром `?api=http://localhost:8000` (запоминается в `localStorage.mp_api_base`, сброс через `?api=reset`).
- Навигация между страницами идёт по прямым именам `.html` (`user_cabinet.html`, `registrar_terminal.html` и т.д.), поэтому фронт работает и с любого статического сервера, и при раздаче с бэкенда.

## 2. Ключевые доменные сущности и правила

### Разделение `Form ID` и `Card ID`
Это центральная идея системы:
1. **`order_id`** — ID заказа (индивидуального или семейного/группового), например `MP2026-FAMILY` или `MP2026-ORD-981240`. Один плательщик оплачивает один заказ за `1..N` участников.
2. **`id` (`Form ID`)** — ID электронной анкеты/билета конкретного участника (формат `MP2026-XXXXXX`). Зашивается в QR-код в Личном кабинете (`user_cabinet.html`) и предъявляется на старте.
3. **`card_id` (`Card ID`)** — номер типографской карты с штрихкодом `CODE128`, выдаваемой волонтёром на старте. Имеет **строгий префикс дистанции**:
   - `10` км → `CARD-10-XXXXX`
   - `17` км → `CARD-17-XXXXX`
   - `33` км → `CARD-33-XXXXX`
   - `50` км → `CARD-50-XXXXX`

### Справочник маршрутов, тарифов и стартовых окон

| `dist` | `route` | `routeName` | Цена (`price`) | Стартовое окно |
| :--- | :--- | :--- | :---: | :--- |
| `"10"` | `"10 км"` | `"10 км «Городской круг»"` / `"Исетский променад"` | `400` ₽ | `11:00 — 13:00` |
| `"17"` | `"17 км"` | `"17 км «Шарташская кругосветка»"` | `450` ₽ | `09:00 — 12:00` |
| `"33"` | `"33 км"` | `"33 км «В Новокольцовский»"` | `500` ₽ | `08:00 — 11:00` |
| `"50"` | `"50 км"` | `"50 км «Классика Прогулки»"` | `600` ₽ | `07:00 — 09:00` |

## 3. Спецификация REST API эндпоинтов

### 3.1. `POST /api/register`

Регистрация одного участника, семейной/групповой заявки, добавление нового участника в существующий заказ или сохранение оцифрованной бумажной анкеты со станции наборщика.

- **Где вызывается:**
  - `user_cabinet.html` (онбординг-мастер регистрации и кнопка «+ Добавить в заказ»)
  - `typist_station.html` (кнопка сохранения распознанной бумажной анкеты)
- **Content-Type:** `application/json`

**Тело запроса (вариант А — новая заявка из ЛК):**
```json
{
  "type": "family",
  "familyName": "Семья Кузнецовых",
  "payerPhone": "+7 912 648-21-90",
  "payerEmail": "alex@example.com",
  "paid": false,
  "participants": [
    {
      "fio": "Кузнецов Михаил Сергеевич",
      "surname": "Кузнецов",
      "name": "Михаил",
      "patronymic": "Сергеевич",
      "role": "Глава семьи / Заявитель",
      "gender": "М",
      "birth": "1986-05-12",
      "phone": "+7 912 648-21-90",
      "email": "alex@example.com",
      "city": "г. Екатеринбург",
      "dist": "33",
      "route": "33 км",
      "soc": "Зарегистрирован онлайн"
    }
  ]
}
```

**Тело запроса (вариант Б — добавление спутника в существующий заказ):**
Содержит дополнительное поле `"order_id": "MP2026-FAMILY"` на верхнем уровне.

**Тело запроса (вариант В — очная анкета со станции наборщика `typist_station.html`):**
Внутри объекта в `participants[0]` дополнительно передаются `"id": "MP2026-042189"` и `"form_id": "MP2026-042189"`, а на верхнем уровне `"paid": true` и `"type": "individual"`. Обратите внимание: `birth` из OCR может прийти в формате `"DD.MM.YYYY"` (например, `"14.06.1992"`), а из веб-формы — в `"YYYY-MM-DD"`.

**Ожидаемый ответ (`200 OK`):**
```json
{
  "status": "success",
  "order_id": "MP2026-ORD-123456",
  "group_code": "MP2026-FAM-123456",
  "total_participants": 1,
  "participants": [
    {
      "id": "MP2026-12345601",
      "order_id": "MP2026-ORD-123456",
      "fio": "Кузнецов Михаил Сергеевич",
      "role": "Глава семьи / Заявитель",
      "gender": "М",
      "birth": "1986-05-12",
      "phone": "+7 912 648-21-90",
      "email": "alex@example.com",
      "city": "г. Екатеринбург",
      "dist": "33",
      "route": "33 км",
      "routeName": "33 км «В Новокольцовский»",
      "soc": "Зарегистрирован онлайн",
      "paid": false,
      "price": 500,
      "card_id": null
    }
  ]
}
```
> **Важно:** `user_cabinet.html` читает `data.order_id`, а `typist_station.html` читает `res.participants[0].id`. Если передан пустой список `participants`, возвращайте `400 Bad Request`.

### 3.2. `GET /api/participants/{lookup_id}`

Умный поиск участника или всей семейной/групповой заявки.

- **Где вызывается:**
  - `user_cabinet.html` — передаёт активный `order_id` из `localStorage.mp_active_order_id` (по умолчанию `'MP2026-FAMILY'`).
  - `registrar_terminal.html` — передаёт значение из поля сканера/поиска на старте.
- **Что может прийти в `{lookup_id}`:**
  1. `Form ID`: `MP2026-849201` (или сокращённо `849201` без префикса `MP2026-`)
  2. `Order ID` / код семьи: `MP2026-FAMILY`, `MP2026-ORD-981240`
  3. `Card ID`: `CARD-33-01452`
  4. Номер телефона (с пробелами/дефисами или цифрами) или подстрока ФИО

**Ожидаемый ответ (`200 OK`):**
```json
{
  "found": true,
  "is_group": true,
  "target": {
    "id": "MP2026-849201",
    "order_id": "MP2026-FAMILY",
    "family_name": "Семья Смирновых",
    "role": "Глава семьи / Заявитель",
    "fio": "Смирнов Алексей Сергеевич",
    "gender": "М",
    "birth": "1988-06-14",
    "phone": "+7 912 648-21-90",
    "email": "alex.smirnov@example.com",
    "city": "г. Екатеринбург",
    "route": "33 км",
    "dist": "33",
    "routeName": "33 км «В Новокольцовский»",
    "soc": "IT-специалист (УрФУ)",
    "paid": false,
    "price": 500,
    "card_id": null
  },
  "members": [
    { "id": "MP2026-849201", "...": "..." },
    { "id": "MP2026-849202", "...": "..." }
  ],
  "order": {
    "order_id": "MP2026-FAMILY",
    "type": "family",
    "familyName": "Семья Смирновых",
    "payer_name": "Смирнов Алексей Сергеевич",
    "payer_phone": "+7 912 648-21-90",
    "paid": false,
    "total_price": 1400
  }
}
```
> **Важно:** если найденный участник входит в групповой заказ, в `members` нужно вернуть **всех участников этого заказа** (так терминал регистратора выдаст карты всей семье по одному QR-коду, а ЛК отобразит всю семью). Если не найдено — возвращайте `404 Not Found` с `{ "detail": "..." }`.

### 3.3. `GET /api/participants`

Получение общего реестра участников (опциональный query-параметр `?q=...` для фильтрации по ID, ФИО, телефону, `order_id`, `card_id`).

- **Где вызывается:**
  - `marker_terminal.html` — модальное окно «Выданные карты» (фильтрует на клиенте участников с непустым `card_id`, чтобы показать их штрихкоды/QR для тестирования КП).

**Ожидаемый ответ (`200 OK`):**
```json
{
  "total": 6,
  "participants": [
    {
      "id": "MP2026-849201",
      "fio": "Смирнов Алексей Сергеевич",
      "route": "33 км",
      "dist": "33",
      "card_id": "CARD-33-01452",
      "paid": true
    }
  ]
}
```

### 3.4. `POST /api/registrar/mark-paid`

Фиксация оплаты заказа или отдельного участника (используется и при онлайн-оплате в ЛК, и при приёме наличных/терминала на старте).

- **Где вызывается:**
  - `user_cabinet.html` (симуляция оплаты СБП/картой)
  - `registrar_terminal.html` (кнопки «Оплатить наличными / картой» или горячая клавиша `Space`)
- **Content-Type:** `application/json`

**Тело запроса:**
```json
{
  "lookup_id": "MP2026-FAMILY",
  "method": "СБП Онлайн"
}
```
> В `lookup_id` может прийти как `order_id` (`MP2026-FAMILY`), так и `id` участника (`MP2026-849201`). Если пришёл `order_id`, нужно пометить оплаченными (`paid: true`) и сам заказ, и всех его участников.

**Ожидаемый ответ (`200 OK`):**
```json
{
  "status": "success",
  "message": "Заказ MP2026-FAMILY оплачен (СБП Онлайн)"
}
```
Если не найден — `404 Not Found`.

### 3.5. `POST /api/registrar/issue-card`

Привязка физической штрихкодовой карты (`CARD-XX-XXXXX`) к участнику на старте.

- **Где вызывается:** `registrar_terminal.html`
- **Content-Type:** **`multipart/form-data`** (`FormData`, **не JSON**!)
- **Поля формы:**
  - `form_id` (`string`, обязательное) — ID отсканированного билета/заказа
  - `card_id` (`string`, обязательное) — штрихкод карты (приводится к uppercase)
  - `route` (`string`, по умолчанию `"33 км"`) — дистанция участника
  - `participant_id` (`string`, опциональное) — конкретный ID участника (особенно важно для семейных заказов, где в одном заказе 3 человека)

**Бизнес-валидации на стороне бэкенда (фронтенд обрабатывает тексты из `detail`):**
1. **Защита от дублей (`409 Conflict`):** если `card_id` уже выдан **другому** участнику, вернуть HTTP `409` с `{ "detail": "Ошибка: Карта CARD-XX-XXXXX уже выдана участнику ..." }`.
2. **Контроль серии карты (`400 Bad Request`):** префикс карты должен соответствовать дистанции (`CARD-10-`, `CARD-17-`, `CARD-33-`, `CARD-50-`). При несовпадении вернуть HTTP `400` с `{ "detail": "..." }`.

**Ожидаемый ответ (`200 OK`):**
```json
{
  "status": "success",
  "message": "Карта CARD-33-01452 успешно привязана к Смирнов Алексей Сергеевич",
  "card_id": "CARD-33-01452",
  "participant_id": "MP2026-849201",
  "total_issued": 1
}
```

### 3.6. `POST /api/scans/batch`

Пакетный приём отметок прохождения КП от мобильных терминалов маркёров (поддерживает как мгновенную отправку онлайн, так и сброс накопившейся офлайн-очереди).

- **Где вызывается:** `marker_terminal.html`
- **Content-Type:** `application/json`

**Тело запроса:**
```json
{
  "cp_id": "КП-1 (Шарташский бор)",
  "scans": [
    {
      "card_id": "CARD-33-01452",
      "timestamp": "14:15:02",
      "route": "33 км"
    }
  ]
}
```

**Ожидаемый ответ (`200 OK`):**
```json
{
  "status": "synced",
  "accepted_count": 1,
  "total_cp_scans": 1
}
```

  "total_started": 14280,

### 3.9. `POST /api/ocr/recognize`

Распознавание рукописной бумажной анкеты на станции наборщика.

- **Где вызывается:** `typist_station.html`
- **Content-Type:** **`multipart/form-data`** (`FormData`)
- **Возможные поля запроса (передаётся одно из трёх):**
  - `file` — загруженный файл изображения (`image/*`)
  - `image_base64` — строка data URL снимка с веб-камеры (`data:image/jpeg;base64,...`)
  - `preset` — ключ демо-пресета (`"smirnov"`, `"ivanov"`, `"petrova"`)

**Три варианта ответа (`200 OK`), которые понимает фронтенд:**

1. **Успешное распознавание:**
```json
{
  "status": "success",
  "is_form": true,
  "overall_confidence": 94.5,
  "data": {
    "surname": "СМИРНОВ",
    "name": "АЛЕКСАНДР",
    "patronymic": "СЕРГЕЕВИЧ",
    "birth_date": "14.06.1992",
    "gender": "Мужской",
    "phone": "+7 (912) 648-21-90",
    "city": "г. Екатеринбург",
    "distance": "33 км",
    "prev_participations": "04",
    "card_number": "042189"
  },
  "image_preview": "data:image/jpeg;base64,..."
}
```
> Поля, на которые смотрит UI: `surname`, `name`, `patronymic`, `birth_date`, `gender` (`"Ж"`/`"F"` или `"М"`), `phone`, `city`, `card_number` (превращается в `MP2026-{card_number}`), `prev_participations`, `distance` (проверяется вхождение `50`, `33`, `17`/`18`, `10`/`15`). `image_preview` опционален.

2. **Пустой (незаполненный) бланк:**
```json
{
  "status": "empty_form",
  "is_form": true,
  "is_empty": true,
  "message": "Бланк анкеты выровнен по 4 реперам, поля пустые.",
  "image_preview": "data:image/jpeg;base64,..."
}
```

3. **На фото не бланк анкеты (нет реперных меток):**
```json
{
  "status": "warning",
  "is_form": false,
  "message": "На снимке не найдены реперы бланка «Майской прогулки»."
}
```

### 3.10. `POST /api/system/reset-db`

Кнопка «Сброс базы» в шапке `user_cabinet.html` для возврата тестового стенда в исходное демо-состояние.

- **Где вызывается:** `user_cabinet.html`
- **Тело запроса:** пустое
- **Ожидаемый ответ (`200 OK`):** `{ "status": "success", "message": "..." }`
> В продакшене этот эндпоинт можно не реализовывать (или закрыть авторизацией), а кнопку «Сброс базы» убрать из `user_cabinet.html`.

## 4. Требования к CORS и проксированию (Nginx)

### Если фронт и бэкенд на разных портах/доменах
Настройте на бэкенде CORS-заголовки:
- `Access-Control-Allow-Origin`: URL фронтенда (или `*` на время разработки)
- `Access-Control-Allow-Methods`: `GET, POST, OPTIONS`
- `Access-Control-Allow-Headers`: `Content-Type, Authorization`

### Если фронт и бэкенд за одним Nginx (рекомендуемый вариант)
Оставьте `DEFAULT_API_BASE_URL = ''` в `api_config.js`, а в Nginx проксируйте `/api/`:

```nginx
server {
    listen 80;
    server_name localhost;

    root /var/www/mayprogulka-frontend;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    location /api/ {
        proxy_pass http://backend:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 20M; # важно для фото анкет в /api/ocr/recognize
    }
}
```

## 6. Чеклист проверки интеграции (E2E)

1. **Онлайн-регистрация и оплата:**
   - Открыть `route_selector.html` → выбрать маршрут → перейти в `user_cabinet.html?route=33`.
   - Заполнить мастер регистрации (в т.ч. семейной) → уходит `POST /api/register`.
   - Нажать «Оплатить» → уходит `POST /api/registrar/mark-paid` → в ЛК появляются QR-коды с `Form ID`.
2. **Выдача карты на старте:**
   - Открыть `registrar_terminal.html`, ввести/отсканировать `Form ID` → уходит `GET /api/participants/{id}`.
   - Если не оплачен — нажать оплату → `POST /api/registrar/mark-paid`.
   - Ввести/отсканировать карту правильной серии (`CARD-33-...`) → уходит `POST /api/registrar/issue-card` (`multipart/form-data`).
   - Проверить негативные кейсы: повторная выдача той же карты (`409`) и карта от другой дистанции (`400`).
3. **Лесной КП и SOS:**
   - Открыть `marker_terminal.html`, отсканировать выданную карту → уходит `POST /api/scans/batch`.
   - Нажать SOS и отправить инцидент → уходит `POST /api/safety/emergency`.
4. **Штаб безопасности:**
   - Открыть `safety_dashboard.html` → убедиться, что `GET /api/safety/alerts` возвращает созданный SOS и на экране появляется красный баннер.
5. **Станция наборщика (OCR):**
   - Открыть `typist_station.html`, выбрать пресет или загрузить фото → уходит `POST /api/ocr/recognize` (`multipart/form-data`).
   - Нажать сохранение → уходит `POST /api/register` → переход на `registrar_terminal.html?form_id=...`.
